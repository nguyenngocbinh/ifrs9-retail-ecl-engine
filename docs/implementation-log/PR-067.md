# PR-067 — Stage 2 EAD checkpoint convention

## Objective
Implement the agreed EAD sampling convention in the upstream Non-Revolving EAD ETL on branch `feat/ead-quarterly-point-discount`.

## Decisions implemented
- Stage 2 with remaining maturity of at least one year: use point-in-time EAD at each annual checkpoint from the reporting date.
- Stage 2 with remaining maturity strictly below one year: average the available EAD balances at the 3-, 6-, and 9-month checkpoints that fall on or before maturity.
- Calendar checkpoints are calculated from `PROCESS_DATE` with `DATEADD(month, ...)`; SQL Server month-end behavior applies where the target day does not exist.
- At each checkpoint, use the latest `EAD_AFTER_REPAYMENT` with `SCHEDULE_DUE_DATE` on or before that checkpoint, so same-day repayment is included.
- Annual checkpoint is capped at maturity for a partial final period.
- EAD remains undiscounted in the upstream loader; EIR discounting stays in the ECL calculation step.

## Validation performed
- Reviewed the SQL change for SQL Server 2016-compatible T-SQL constructs.
- Confirmed the implementation preserves the existing annual `ecl_stg.EADCurve` grain and does not add discounting to EAD.
- SQL Server integration tests were not run in this environment. Validate against a non-production database with synthetic cases for: annual checkpoints, maturity below one year, month-end checkpoints, same-day repayment, no quarterly checkpoint before maturity, and partial final annual period.

## Known limitation / review point
The quarterly rule averages only checkpoint balances available on or before maturity; if none exists, it falls back to `EAD_0`. Confirm this fallback is acceptable for very short remaining maturities (under three months) during methodology review.
