# PR 063 — Calculate annual time-weighted average EAD

## Summary
- Replace the year-end balance lookup in `ecl_core.usp_StageSourceEADCurve` with a calendar-day-weighted average over each annual forecast period.
- Use the source reporting-date balance and schedule balance changes as event boundaries; each balance is weighted by the number of days it is effective within the period.
- Preserve Stage 3 as period 1 using `EAD_0` pending confirmation of the Stage 3 exposure basis.
- Keep `ecl_core.usp_LoadEADCurve` unchanged and validation-only.

## Formula
`EAD_average(n) = SUM(balance_i * days_i) / days_in_period(n)`

Annual periods use half-open boundaries `[DATEADD(year,n-1,PROCESS_DATE), DATEADD(year,n,PROCESS_DATE))`. Schedule balances become effective on their due date. The implementation includes a zero-balance interval after maturity within the final generated annual period.

## Test cases required before merge
1. Constant balance throughout a full annual period: average equals the constant balance.
2. A principal repayment midway through the period: average equals the day-weighted balance before and after the due date.
3. Full repayment midway through a period: average is positive for the outstanding part and zero thereafter.
4. Multiple repayment dates and a leap-year period.
5. Schedule due on the period start and on the period end boundary.
6. Stage 3: exactly period 1 and EAD equals reporting-date `EAD_0`.
7. Missing/invalid schedule values, negative EAD, and duplicate schedule events on the same date.
8. Accounts already loaded by a product-specific ETL remain untouched.
9. Required horizon and EAD row counts reconcile with the active AccountSnapshot population.

## Unresolved methodology/source questions
- This is a proposed convention and is not approved bank policy. Confirm the uniform-within-year default timing assumption and the use of calendar-day weighting.
- The current DB2 source procedure may emit a synthetic row at PROCESS_DATE when no future schedule exists. This SQL Server procedure cannot distinguish that synthetic row from a contractual event using the currently documented source contract. Confirm the desired fallback for positive balance with no future contractual schedule before production use.
- Stage 3 uses `EAD_0`, not a forward-year average, pending methodology-owner confirmation.
- Discounting was not changed.
