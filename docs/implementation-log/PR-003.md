# PR #3 — Logical schema and canonical table design

## Status
Proposed in branch `design/pr-003-logical-schema-review`; review required. Not merged.

## Goal
Implement the user's chosen design: functional schemas, normalized separate inputs, shared result tables, account-level reporting grain, shared product discriminator, and management fields PROCESS_DATE, RUN_ID, VERSION_ID, IS_ACTIVE.

## Decisions encoded
- Schemas: ecl_cfg, ecl_stg, ecl_core, ecl_result, ecl_audit.
- One shared product type dimension for Mortgage, Auto, Credit Card, Personal Loan, and Other Retail.
- Normalized tables for account/stage/pool, PD, LGD, EAD, EIR, scenario weights.
- RUN_ID isolates execution snapshots; PROCESS_DATE is explicit on run/input/output/audit rows.
- VERSION_ID and IS_ACTIVE are carried on versioned inputs; run history must not be altered by changing active flags.
- Approved PD grain: run/account/scenario/forecast period.
- Approved LGD grain: run/account/forecast period.
- Approved EAD grain: run/account/forecast period.
- EIR grain: run/forecast period, shared across accounts/products/pools.
- Portfolio summary stores both portfolio and pool rows with explicit aggregation level.
- Stage 3 approach selected as PD=1, but allocation of EAD/LGD and period-level loss treatment remain unresolved; no formula is implemented.
- Detail result grain is run/account/scenario/forecast period; account result grain is run/account.
- Run event and validation-error tables support auditability and pre-calculation gates.
