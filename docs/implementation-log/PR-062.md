# PR 062 — Preserve outstanding EAD when no future schedule exists

## Summary
- Change `RM_RDM_MOP_PROD.SP_CALC_NONREVOLVING_EAD` from an inner join to a left join for future principal schedule rows.
- Preserve every account present in the CL020 reporting-date balance snapshot, including accounts with no future principal rows.
- For an account with no future principal schedule, emit one synthetic schedule row dated `PROCESS_DATE`, with zero principal repayment and `EAD_AFTER_REPAYMENT = EAD_0`.
- Update `ecl_core.usp_StageSourceEADCurve` to create period 1 for Stage 3 and already-matured accounts, in line with the canonical EAD loader/calculation convention.
- Document that the SQL Server annual EAD source ETL can then carry the current balance forward for each required year-end period.
- Keep `ecl_core.usp_LoadEADCurve` strict: the loader continues to require real, active VND EAD rows in every required period. The fix supplies the missing rows upstream rather than weakening validation.

## Methodology assumption
When a non-revolving account has a positive reporting-date outstanding balance but no future contractual principal schedule, the fallback holds its balance at `EAD_0` for each required annual period. This prevents the account from disappearing from EAD staging, but it does not infer an amortization schedule that is not present in source data. Confirm this fallback with the methodology/source owner before production use.
