# PR #28 — Source mapping register and SQL Server 2016 test harness

## Purpose

Advance the two requested workstreams without inventing upstream metadata or claiming runtime test results that have not run.

## Scope

- Add a field-level mapping register from each logical input family to its canonical staging/configuration table and required columns.
- Identify source object/column names as unresolved until approved upstream DDL/data dictionary/interface specifications are supplied.
- Add a manually triggered SQL Server 2016 workflow for a controlled Windows self-hosted runner with SQL Server 2016 and sqlcmd installed.
- The workflow checks major version 13, creates an isolated test database, deploys migrations 001–004, runs all current SQL smoke/regression tests, and attempts cleanup.
- Update the project roadmap.

## Guardrails

- No production/source-system survey and no customer data.
- No fabricated source table/column names.
- No final ECL formula implementation.
- SQL Server 2016 compatibility is not considered verified until the workflow actually runs successfully against a server reporting major version 13.

## Required setup / limitations

- Configure a controlled self-hosted Windows runner with labels `self-hosted`, `windows`, `sql-server-2016`.
- Install SQL Server 2016 and `sqlcmd` on the runner; configure repository secrets `SQLSERVER_2016_INSTANCE`, `SQLSERVER_2016_USER`, and `SQLSERVER_2016_PASSWORD` for a disposable test instance.
- Supply approved upstream source DDL/data dictionary/interface specifications to close the source mapping.
