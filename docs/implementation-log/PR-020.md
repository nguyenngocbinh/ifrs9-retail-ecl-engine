# PR-020 — Initial pre-calculation input validation

## Goal

Add a guarded validation procedure that runs after input loading/sealing and before any future ECL calculation.

## Included

- \`database/003_input_validation.sql\` adds nullable \`IS_POCI\` to the account snapshot. NULL is intentionally treated as unknown, not as non-POCI.
- Adds \`ecl_core.usp_ValidateRunInputs\`, which requires run status \`VALIDATING\` and checks:
  - sealed manifest and all six required input families;
  - active account population and selective-run scope;
  - maturity date consistency;
  - explicit POCI classification; identified POCI accounts currently create an ERROR finding because calculation exclusion/reconciliation is not yet implemented;
  - selected scenario-weight version effective on the process date and active Downturn/Base/Upturn weights summing to 1;
  - required annual PD by account/scenario/period, LGD and EAD by account/period, and shared EIR period coverage through maturity.
- Writes findings to \`ecl_audit.ValidationError\` and an \`INPUT_VALIDATION\` event to \`ecl_audit.RunEvent\`. ERROR/FATAL findings remain blocked by the existing transition gate before calculation.
- Adds synthetic negative-path test coverage and wires migration 003 plus the test into GitHub Actions.

## Methodology and safety guardrails

- No ECL formula, account ECL, or summary amount is calculated.
- Annual PD and EAD curves are not prorated for partial final periods; this procedure only checks period coverage.
- POCI remains out of v1. Until calculation exclusion and reconciliation are implemented, detected POCI is an ERROR and blocks calculation. A later change may relax this to WARN only when exclusion and reconciliation are demonstrably enforced.
- No source survey, customer data, credentials, or production database access.

## Validation status and limitations

- The new migration and tests are wired into the repository's SQL Server integration workflow.
- Await the PR workflow result before treating the SQL as integration-tested.
- The hosted workflow currently uses SQL Server 2017 Linux. SQL Server 2016 compatibility remains to be verified separately.
- Validation is an initial gate, not a complete canonical input contract. EIR rate basis/source-period mapping, scenario-weight provenance, input snapshot row-count reconciliation, and further edge cases remain follow-up items.
