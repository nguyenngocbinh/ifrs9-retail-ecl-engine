# PR #45 — Shared EAD loading and validation

## Summary

- Add `ecl_core.usp_LoadEADCurve @RUN_ID` as a shared validation step for Auto, Non-Revolving Personal Loan, and other retail products.
- Keep `ecl_stg.EADCurve` as the single canonical EAD input table consumed by the ECL engine.
- Do not create a second `ecl_stg.EADCurveInput` table or copy rows between equivalent staging tables.
- Add synthetic SQL Server 2022 regression coverage and include migration 006 in CI.

## Design

Product-specific ETL calculates one annual EAD value per `RUN_ID + ACCOUNT_ID + FORECAST_PERIOD` and inserts it directly into `ecl_stg.EADCurve`. The shared procedure validates that the run exists and is pre-calculation, process dates match, EAD is non-negative and in VND, and every active account has active EAD coverage for every annual period through maturity (maximum 120 periods). It then records the successful validation in `ecl_audit.RunEvent`.

The procedure does not copy, transform, or calculate EAD. The ECL calculation procedure remains unchanged.
