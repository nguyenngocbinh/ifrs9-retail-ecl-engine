# PR-018 — Implement run manifest and guarded lifecycle procedures

## Goal
Implement the minimum SQL Server 2016 run-control primitives needed for reproducible runs, based on the approved run-control design.

## Included
- `database/002_run_control.sql`: run-to-input-version manifest header and family items.
- Guarded procedures to create a run, register input versions, seal the manifest, record reconciliation/publication milestones, and transition run status.
- Application locks for lifecycle/sealing operations.
- Triggers preventing manifest-item mutation after sealing and preventing a sealed header from being reopened.
- `tests/sql/run_control_smoke_tests.sql`: transactional synthetic smoke test for the happy path, immutable manifest, milestone gates, and terminal-state rejection.
- This per-PR implementation log.

## Safety and methodology
- No ECL calculation formulas or customer/source data.
- No physical source survey.
- No source credentials or secrets.
- No production database deployment.
- Scenario-weight version is explicitly bound at run creation; input families record source/version identifiers, row counts, completeness, and optional SHA-256-sized hash bytes.

## Validation performed
- Static review for SQL Server 2016-compatible T-SQL constructs.
- The smoke-test script is provided but has **not** been executed against SQL Server 2016 in this environment.
- Deployment requires the logical schema migration `database/001_create_logical_schema.sql` first and must be tested in a disposable database.
- Permissions must restrict direct DML on run/manifest/audit tables; procedures and triggers provide guardrails but do not replace least-privilege deployment roles.

## Known limitations / next gates
- Manifest registration records declared source/snapshot metadata; it does not itself load or hash source rows.
- Complete row-level validation, scenario-weight sum validation, curve coverage/maturity validation, and reconciliation computation remain separate work.
- A successful reconciliation event must be produced by a future reconciliation component; this PR only gates state transitions on the recorded event.
- Do not implement final ECL formulas until methodology blockers are approved.
