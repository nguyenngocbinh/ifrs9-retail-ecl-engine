# PR-021 — Input manifest reconciliation and POCI audit

## Scope

- Adds `database/004_input_reconciliation.sql` with `ecl_core.usp_ReconcileInputSnapshots`.
- Compares sealed manifest row counts to staged row counts for ACCOUNT, PD, LGD, EAD, EIR and selected scenario-weight version.
- Checks all staged process dates against the run date.
- Reports active population, detected POCI and unclassified POCI counts.
- Records `MANIFEST_COUNT_MISMATCH`, `STAGING_DATE_MISMATCH`, `POCI_RECON_UNKNOWN`, and `POCI_RECON_BLOCKED` as ERROR findings.
- Records `INPUT_RECONCILIATION` events, deliberately separate from the `RECONCILIATION` publication gate.
- Includes transactionally rolled-back synthetic negative-path tests and CI wiring.

## Important limits

- Reconciles physical staging row counts, including inactive rows. The source contract must certify that the manifest uses that same count definition.
- No account-level ECL, scenario ECL, or final publication.
- Until downstream exclusion and reconciliation are enforced, any detected POCI continues to block calculation.
- Repeated identical mismatches do not duplicate the same findings, but each invocation adds a separate audit event.
- Procedure runs only in VALIDATING status with a sealed manifest; no production/source data access.
- The current CI image is SQL Server 2017 Linux; compatibility with SQL Server 2016 still requires explicit verification.
- Full publication reconciliation, positive-path account/portfolio totals, and atomic publication remain future work.
