# PR 051 — Optimize source LGD curve staging

## Summary
- Optimize `ecl_core.usp_StageSourceLGDCurve` after reviewing the supplied SQL Server execution-plan XML.
- Materialize one source LGD observation per active account before annual expansion and calculate the annual horizon once.
- Validate source completeness, uniqueness, LGD range, and maturity horizon before expansion.
- Replace the `sys.all_objects` cross join used for row generation with a bounded 1..120 numbers set.
- Add a clustered unique index on `#MappedLGD(RUN_ID, ACCOUNT_ID, FORECAST_PERIOD)` to support coverage checks and enforce canonical key uniqueness.
- Preserve annual horizon semantics, flat LGD in v1, replace-by-RUN_ID transaction safety, and audit behavior.

## Evidence
The supplied plan for the final maturity coverage check shows table scans of `#MappedLGD` reading an estimated 439,834 rows in the period-1 existence branch and the grouped maximum-period branch. The plan also shows `AccountSnapshot` sought through its clustered primary key on `RUN_ID`, with `PROCESS_DATE` and `IS_ACTIVE` as residual predicates.
