# PR 051 — Optimize source LGD curve staging

## Summary
- Investigate the runtime of `ecl_core.usp_StageSourceLGDCurve` using the supplied SQL Server execution plan.
- Reduce repeated scans of the expanded `#MappedLGD` validation set by validating one row per account before expansion and indexing the mapped table for its canonical key.
- Preserve source uniqueness/completeness/range validation, annual horizon semantics (up to 120 years), replace-by-RUN_ID transaction safety, audit event, and canonical LGD grain.

## Evidence
The supplied actual-plan XML excerpt for the final maturity coverage check shows table scans of `#MappedLGD` with 439,834 estimated rows read in the period-1 existence branch and in the grouped maximum-period branch. `AccountSnapshot` is accessed through the clustered primary key on `RUN_ID`, while PROCESS_DATE and IS_ACTIVE remain residual predicates.

## Implementation approach
- Add `#SourceLGD` as a materialized one-row-per-active-account staging set after source data-quality checks.
- Compute the annual horizon once when creating `#SourceLGD`.
- Validate invalid/null/over-120-year horizons before row expansion.
- Expand using a fixed numbers source 1..120 rather than a cross join of `sys.all_objects`.
- Add a clustered unique index on `#MappedLGD(RUN_ID, ACCOUNT_ID, FORECAST_PERIOD)` immediately after expansion. This supports canonical duplicate detection and period-1/account coverage probes without repeated full scans.
- Keep the view and source key columns unchanged. Physical source view indexing cannot be safely prescribed without its underlying definition.
