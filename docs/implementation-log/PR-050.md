# PR 050 — Canonical AccountSnapshot loader

## Summary
- Add `database/upstream/002_load_account_snapshot.sql`.
- Create `ecl_cfg.PoolProductTypeMap` as an explicit, governed mapping from `POOL_ID` to canonical `PRODUCT_TYPE`.
- Add `ecl_core.usp_LoadAccountSnapshot`, which consumes `ecl_stg.AccountStagePoolSource`, reads contract `expiry_date` as `MATURITY_DATE`, and inserts rows into `ecl_stg.AccountSnapshot`.
- Preserve the canonical grain `RUN_ID + ACCOUNT_ID`, run-date/version checks, Stage/Pool values from the preceding loader, manifest-seal protection, transaction boundaries, and an audit event.
- Refuse to load when any pool lacks an active product mapping, maturity is missing/invalid or earlier than PROCESS_DATE, or source contract cardinality is not exactly one.
- Refuse replacement after manifest sealing or when dependent curves/results already exist.

## Product mapping gate
The procedure intentionally does not guess mappings from pool names. `RETAIL_LN_AUTO → AUTO`, `RETAIL_LN_MORTGAGE → MORTGAGE`, and `RETAIL_CARD → CREDITCARD` are shown only as candidate examples in documentation and must be approved before configuration. Remaining pool mappings must be confirmed by the product taxonomy owner.

## Run order
1. Apply migrations `database/001_create_logical_schema.sql` and `database/002_run_control.sql`.
2. Apply `database/upstream/001_load_account_stage_pool_source.sql`.
3. Apply `database/upstream/002_load_account_snapshot.sql`.
4. Configure approved `ecl_cfg.PoolProductTypeMap` entries.
5. Run `ecl_core.usp_LoadAccountStagePoolSource`.
6. Run `ecl_core.usp_LoadAccountSnapshot`.
