# PR 049 — Contract-level Stage and pool join keys

## Summary
- Clarify how customer-level Stage results are expanded to contract-level ECL inputs.
- Use CONTRACT_ID as ACCOUNT_ID; never substitute CUSTOMER_ID for the account key.
- Specify the join keys PROCESS_DATE + CUSTOMER_ID + SEGMENT_ODR_LV1.
- Document the segment normalization needed when the raw contract source exposes segment_lv1/segment_lv2/modul rather than a pre-normalized segment_odr_lv1 column.
- Add LEFT JOIN-based SQL reference and quality checks for missing mappings and duplicate contract expansion.

## Source logic preserved
Stage is derived from the final bucket in DEFAULT.dbo.CUSTOMER_ODR_LRA_IRB. The source process aggregates at customer/segment level and applies additional OD and Corporate bucket adjustments. The ECL loader should consume this finalized bucket rather than recalculate Stage from each contract's DPD/MOB.

## Validation and limitations
- Documentation-only change; no production database queried and no SQL/CI execution claimed.
- The source schema must be checked to confirm whether ODR_CONTRACT_LEVEL_IRB has a pre-normalized segment_odr_lv1. If not, the documented CTE derives the same normalized segment from source segment fields.
- Before production use, verify that PROCESS_DATE + CUSTOMER_ID + SEGMENT_ODR_LV1 is unique in CUSTOMER_ODR_LRA_IRB and that each PROCESS_DATE + CONTRACT_ID expands to exactly one canonical account row.
- The follow-up loader in PR #50 now carries forward the mapped `POOL_NAME`, reads `MATURITY_DATE` from `expiry_date`, and uses the controlled `RUN_ID`/`VERSION_ID` contract. Physical source DDL and end-to-end execution still require verification.

## SQL entry point
- `database/upstream/001_load_account_stage_pool_source.sql`
- Creates `ecl_stg.AccountStagePoolSource` and `ecl_core.usp_LoadAccountStagePoolSource`.
- The procedure uses the run's PROCESS_DATE, joins on PROCESS_DATE + CUSTOMER_ID + SEGMENT_ODR_LV1, maps CONTRACT_ID to ACCOUNT_ID, checks duplicate source keys and missing Stage mappings, and preserves the final source bucket.
- It deliberately does not write `ecl_stg.AccountSnapshot`: the canonical POOL_NAME catalog and MATURITY_DATE source are now handled by the follow-up AccountSnapshot loader in PR #50.
